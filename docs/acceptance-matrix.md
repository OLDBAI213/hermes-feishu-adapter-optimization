# 飞书适配优化验收矩阵

日期：2026-05-24

## 目标

本项目只解决飞书和 Hermes 之间的适配问题：消息是否完整进入 Hermes，结果是否稳定回到飞书，失败是否能被用户看懂。

不改变当前飞书显示形式；三状态显示、工具记录样式、正文美化属于 `hermes-feishu-display-plus`。

## 模块矩阵

| 模块 | 用户场景 | 必须保证 | 失败表现 | 当前验证 |
|------|----------|----------|----------|----------|
| 文字输入 | 飞书发普通问题 | Hermes 收到原文 | 没反应、内容缺字、乱码 | `verify.ps1` 网关状态 + 飞书基础测试 |
| 图片输入 | 飞书发单张图片 | 模型拿到图片本体，不看到本地路径 | 要求调用视觉模型、读本地文件、看不到图 | `test_image_routing.py`、native image 检查 |
| 图文混排 | 一段文字加图片 | 正文和图片都保留 | 只剩图片、只剩文字、顺序混乱 | `test_feishu.py` + 手工样例 |
| 文件输入 | 飞书发普通文件 | 可下载则保存，不可下载给中文原因 | 静默失败、重复提示、路径泄漏 | 下载失败提示检查 |
| 音视频输入 | 飞书发音频/视频 | 至少进入统一资源下载链路 | 当作普通文本丢失 | `_download_feishu_message_resource` 检查 |
| 忙碌队列 | Hermes 正在工作时继续发消息 | 后发消息和附件进入队列 | 附件丢失、只排队文本 | busy queue media 测试 |
| `/retry` | 用户重试上一轮 | 纯文本可重试；媒体历史必须明确拒绝，不能假装附件重试成功 | 显示成功但实际没附件 | retry media rejection fixture |
| 输出正文 | Hermes 回复飞书 | 保持当前 `post` 形式 | Markdown 原样外露、段落乱序 | Markdown post 检查 |
| 工具记录 | 一轮里多次工具调用 | 记录可见，次数真实 | 不显示、次数假写、英文残留 | run progress 测试 |
| 生命周期 | 网关重启/关闭/上线 | 飞书 home channel 有提示 | 聊着聊着断了但用户不知道 | gateway lifecycle 检查 |

## 分界线

适配优化负责：

- 图片、文件、音频、视频能否被接收和保存。
- 资源失败时是否有明确中文提示。
- 忙碌队列、重试、跨平台继续时是否丢消息。
- 飞书 `post` 输出是否能承载当前内容。
- 网关状态是否可解释。

显示增强负责：

- 三状态显示的文案和样式。
- 工具调用记录的排版、emoji、编号视觉。
- 长文本在电脑和手机上的阅读体验。
- 卡片、分隔线、标题层级、美观程度。

中文化负责：

- 固定英文词、状态词、按钮词、错误词的中文映射。
- 不负责改变消息结构。

## 打包前门槛

任何提交前必须至少满足：

1. `verify.ps1` 通过。
2. 涉及输入、媒体、工具记录、网关生命周期时，`verify.ps1 -Full` 通过。
3. `tests/feishu_acceptance_harness.py` 的固定 fixture 通过，不能只看源码标记。
4. `examples/manual-feishu-cases.md` 中相关场景已手工确认或明确标记未测。
5. `docs/status.md` 记录现象、根因、处理、验证、是否重启。
6. 不把显示增强项目的问题混入适配优化提交。
