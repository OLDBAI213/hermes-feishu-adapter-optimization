# 飞书手工验收样例

这些样例用于真实飞书端验证。自动测试通过后，再用这里的场景确认用户能看到正确结果。

## 执行前确认

- Hermes Gateway 正在运行。
- 飞书 websocket 已连接。
- `E:\AI\hermes\config.yaml` 中 `feishu.outbound_format: post`。
- `runtime_footer.enabled: false`，避免状态卡影响当前显示形式。
- 改过 Hermes 本体后已经重启 Gateway。

## A. 基础输入

### A1 普通文字

发送：

```text
帮我用一句话回复：你现在能收到飞书消息吗？
```

通过标准：

- 飞书收到 Hermes 回复。
- 回复不出现内部路径、堆栈、英文状态残留。

### A2 中文长文本

发送一段 300 字左右中文说明，让 Hermes 总结为 3 点。

通过标准：

- 原文没有被截断。
- 回复段落顺序正常。

## B. 图片和图文混排

### B1 单图

发送一张截图，不加文字。

通过标准：

- Hermes 按图片内容回答。
- 不要求用户再“调用视觉模型”。
- 回复中不出现 `E:\AI\hermes\image_cache`、`MEDIA:`、`vision_analyze`。

### B2 图文混排

发送：

```text
看看这张图的问题在哪里，按 1、2、3 说。
```

同时附一张截图。

通过标准：

- Hermes 同时理解文字要求和图片内容。
- 不只回答“我看不到图片”。
- 不把图片本地路径当作用户正文。

### B3 连续两张图

连续发送两张截图，让 Hermes 比较差异。

通过标准：

- 至少能识别两张图都存在。
- 不把上一张图误当成当前唯一图片。

## C. 文件和资源

### C1 普通小文件

发送一个 `.txt` 或 `.md` 文件。

通过标准：

- 可下载时，Hermes 能读取或说明已收到文件。
- 不可下载时，飞书出现一次中文失败原因。

### C2 非图片文件

发送 `.pdf`、`.docx`、`.xlsx` 任一文件。

通过标准：

- 不静默丢失。
- 不重复刷失败提示。
- 不把临时文件路径当作回答正文。

### C3 音频或视频

发送一个小音频或短视频。

通过标准：

- 进入文件资源处理链路。
- 如果当前能力不能直接理解内容，必须明确说明限制，而不是假装看过。

## D. 会话连续性

### D1 忙碌时追发文字

让 Hermes 执行一个较长任务时，再发一条新消息。

通过标准：

- 新消息进入队列。
- 不打断当前任务。
- 后续处理时不丢内容。

### D2 忙碌时追发图片

长任务期间再发一张图片。

通过标准：

- 图片不会降级成纯文本。
- 后续轮次仍能看到图片。

### D3 重启 Gateway

聊天过程中重启 Hermes Gateway。

通过标准：

- 飞书 home channel 收到重启/上线提示。
- 重启后继续发消息可用。

## E. 输出兼容

### E1 Markdown 正文

让 Hermes 输出包含标题、列表、加粗、代码块的回答。

通过标准：

- 飞书 `post` 显示顺序正确。
- 不出现大量原始 Markdown 符号。

### E2 工具调用记录

让 Hermes 执行会调用多个工具的任务。

通过标准：

- 工具调用记录可见。
- 标题是中文。
- 次数随真实工具调用增加，不是固定写死。

## 记录格式

每次手工验收后，在 `docs/status.md` 追加：

```text
场景：
结果：
问题：
是否重启 Gateway：
对应自动检查：
```
